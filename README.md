# 指標1：単元目標準拠ルーブリック評価（主指標）

- **評価枠組み**：単元目標準拠ルーブリック（要素別 A/B/C，総合 S/A/B/C）
- **評価実行日**：2026年5月19日

## 1.1 使用モデル

| プロバイダ | モデル名 | 役割 |
|---|---|---|
| OpenAI | `gpt-5.5` | Judge 1 |
| Anthropic | `claude-opus-4-7` | Judge 2 |
| Google | `gemini-3.1-pro-preview` | Judge 3 |

3モデルによる Panel of LLM Evaluators 構成（Verga et al., 2024）を採用．異なる開発者・アーキテクチャの独立評価により，モデル内バイアスへの頑健性を担保する．

## 1.2 APIパラメータ（実行時の実値）

| パラメータ | OpenAI `gpt-5.5` | Anthropic `claude-opus-4-7` | Google `gemini-3.1-pro-preview` |
|---|---|---|---|
| temperature | 指定なし（デフォルト=1.0）※1 | 指定なし（デフォルト）※2 | **0.2** |
| seed | **2026** | 非対応 | 非対応 |
| 出力フォーマット指定 | `response_format={"type": "json_object"}` | 指定なし（プロンプト指示のみ） | `response_mime_type="application/json"` |
| 最大トークン | `max_completion_tokens=2000` | `max_tokens=1500` | `max_output_tokens=2000` |
| 同一サンプル採点回数 (`N_RUNS`) | **3**（Self-consistency） | **3** | **3** |

- ※1：GPT-5 系は API 仕様上 `temperature` 指定が無効化されているため，デフォルト値（=1）で実行．
- ※2：Claude Opus 4.7 でも `temperature` 指定が deprecated のためデフォルトで実行．
- 上記の温度差については，**同一サンプル3回採点の最頻値（Self-consistency, Wang et al., 2023）**を採用することで揺らぎを集約し，モデル間で同等の安定性を確保した．

### 共通設定

- リトライ：`tenacity` で最大3回，指数バックオフ（multiplier=2, min=2s, max=20s）
- 並列度：ThreadPoolExecutor で最大8並列
- 採点総数：148サンプル × 3モデル × 3回 = **1,332回採点**

## 1.3 システムプロンプト（全LLM共通）

````
あなたは小学校国語科の指導経験を持つ評価専門家です．小学校4年生の児童が『ごんぎつね』（物語文）の各場面の学習で記述した振り返り文を，単元目標準拠ルーブリック（要素別A/B/C，総合S/A/B/C）で評価してください．

【本実践における中核目標（展開部）】
本文の根拠を示しながら，登場人物の心情や情景を読み取り，他者の考えを踏まえて自分なりの考えを深める．

【評価の3要素】
- 要素A（本文根拠の明示）：本文中の登場人物の行動・描写・記述を具体的に引用または参照しているか
- 要素B（心情・情景の読み取り）：登場人物の気持ちの変化・性格・情景を場面の移り変わりと結び付けて読み取れているか
- 要素C（他者参照を踏まえた自己の解釈の統合）：要素A・Bを踏まえ，他者の考えを取り込みながら自分なりの解釈を論理的・関係的に構成しているか．他者参照の影響は明示的（「友達の意見で」等）・黙示的（初発の感想からの変化）の両方を評価対象とする．

【要素別判定基準】
■ 要素A
A：本文中の具体的な行動・描写・記述を引用または参照（複数または1つでも具体的）
B：本文根拠の言及はあるが具体性が乏しいか1要素のみ
C：本文根拠の言及がない，または無関係な記述
■ 要素B
A：心情を本文根拠と結び付け，場面の移り変わりとの関連も示す
B：心情の読み取りはあるが場面の結び付きが弱いか単一側面のみ
C：心情の読み取りが表層的（「かわいそう」のみ）か未記述
■ 要素C
A：要素A・Bを統合し，他者参照を踏まえた解釈の更新が明示的または黙示的に確認できる
B：要素A・Bが並列的．他者参照への言及はあるが取り込みが弱い，または他者参照への言及自体がない
C：活動の感想のみ，または無関係な記述に終始

【集約ルール（要素別→暫定総合判定）】
1. 3要素全てA → 暫定A
2. 2要素がA，1要素がB → 暫定A
3. 1要素以上がCを含む場合は最高でも総合B
4. 2要素以上がC → 総合C
5. それ以外 → 総合B

【Sへの昇格判定】
暫定総合判定がAの場合に限り，以下のいずれかが認められれば総合S：
- 抽象化：他作品・自己経験・人間関係の真実への一般化
- 批判的考察：登場人物の行動・心情への批判的視点
- 作品全体の主題への到達（すれ違い・後悔・贖罪等）
認められない場合 → 総合A確定

【留意事項】
- 文字数の多少は判定基準ではない
- 個人的体験への過度な脱線は要素C加点に含めない
- 「先生」「みんな」のような曖昧な参照は要素Aの本文根拠としては弱い
- 漢字・誤字脱字は判定対象外

【出力フォーマット（JSON形式）】
必ず以下のJSON形式で出力してください．他の説明文や前置きは不要です．

{
  "要素A_本文根拠": "A" or "B" or "C",
  "要素B_心情読み取り": "A" or "B" or "C",
  "要素C_解釈統合": "A" or "B" or "C",
  "暫定総合判定": "A" or "B" or "C",
  "S昇格条件_該当有無": "あり" or "なし",
  "総合判定": "S" or "A" or "B" or "C",
  "判定理由": "50字以内で簡潔に判定根拠を述べる"
}
````

> 補足：Google Gemini ではシステムプロンプトとユーザメッセージを分離せず，1つの `contents` として `システムプロンプト + "\n\n" + ユーザメッセージ` の形で送信した．

## 1.6 Self-consistency 集約処理

同一サンプルに対する3回採点を以下の2段階で集約した（Wang et al., 2023）．

### モデル内集約（3回採点 → 1モデル判定）

```python
from collections import Counter

def aggregate_within_model(judgments_3runs):
    """3回採点 → 最頻値（2回以上一致）または順序尺度の中央値."""
    valid = [j for j in judgments_3runs if j in ("S", "A", "B", "C")]
    if not valid:
        return None
    counts = Counter(valid)
    most_common = counts.most_common()
    if most_common[0][1] >= 2:
        return most_common[0][0]
    # 全て異なる場合は順序尺度で中央値（C=1, B=2, A=3, S=4）
    rank_map = {"C": 1, "B": 2, "A": 3, "S": 4}
    rev_map  = {v: k for k, v in rank_map.items()}
    ranks = sorted(rank_map[s] for s in valid)
    return rev_map[ranks[len(ranks) // 2]]
```

### モデル間集約（3モデル判定 → 最終判定）

```python
def aggregate_across_models(judgments_3models):
    """3モデルの判定 → 順序尺度の中央値（最終採用値）."""
    valid = [j for j in judgments_3models if j in ("S", "A", "B", "C")]
    if not valid:
        return None
    rank_map = {"C": 1, "B": 2, "A": 3, "S": 4}
    rev_map  = {v: k for k, v in rank_map.items()}
    ranks = sorted(rank_map[s] for s in valid)
    return rev_map[ranks[len(ranks) // 2]]
```

要素別判定（A/B/C 3段階）についても，同一の方式で「モデル内最頻値 → モデル間中央値」を算出した．

# 指標2：SOLOタクソノミー評価（補助指標）

本論文ではSOLOタクソノミー（Biggs & Collis, 1982）を**補助指標**として用い，単元目標準拠ルーブリックとの対応関係（Spearman *ρ* = .813，*n* = 148）から両指標の関係を確認している．改稿にあたり，SOLOの評定は**他者参照に関わる表現を判定の手がかりとしない基準**（下記2.3）により，主指標と同じ3モデル・同じ手続きで再評定した．本論文の分析に用いたSOLOの値はこの再評定の結果であり，初回投稿時に用いた先行評定（単一モデル，判定例つきの旧基準）は本論文の分析には用いていない．

- **評価枠組み**：SOLOタクソノミー（Pre-structural〜Extended Abstract の5階層，Level 1〜5）
- **評価実行日**：2026年10月17日
- **対象**：振り返り記述148件（主指標と同一．児童の姓は〇〇に置換して送信）

## 2.1 使用モデル

指標1と同一（OpenAI `gpt-5.5`，Anthropic `claude-opus-4-7`，Google `gemini-3.1-pro-preview`）．3モデルによる Panel of LLM Evaluators 構成．

## 2.2 APIパラメータ

指標1と同一（temperature等の設定，JSON出力，1記述ずつの絶対評価，同一記述を3回採点，8並列）．採点総数は148記述 × 3モデル × 3回 = 1,332回．Few-shot例は与えず，基準と判定手順の説明のみを与えた（判定例を評価対象の記述から選ぶと評価対象との重複が生じ，また例示に他者参照への言及が含まれうるため）．

## 2.3 システムプロンプト（全LLM共通）

旧基準からの主な変更点：(1) 学習活動・学習方法・他者とのやりとりの記述は，種類を問わず要素に数えない．(2) 考えの出どころ（自分で考えたか，友達から得たか）は判定に用いない．(3) 考えの変化そのものはレベルの根拠にしない．(4) 関係構造（Level 4）は，要素どうしの結び付きが2つ以上組み合わさってまとまった説明になっている記述とし，結び付きが1つだけの記述は多重構造（Level 3）とする．(5) 拡張抽象（Level 5）は，具体を超えた一般化・抽象化がある場合に限る．(6) 中間判断（要素の数，結び付きの数，一般化の有無）をJSONで出力させ，判定手順との整合を事後に確認する（整合率100%，1,332回）．

````
# 役割
あなたは小学校国語科の評価の専門家です。小学校4年生が物語文『ごんぎつね』（新美南吉）の各場面の学習後に書いた振り返り記述を1件読み、SOLOタクソノミーに基づいて、記述に表れた物語の理解の構造的な複雑さを5段階（Level 1〜5）のいずれか1つで判定してください。

# 前提
- 教材：小学校4年生 国語「ごんぎつね」（新美南吉）
- 単元の目標：登場人物の気持ちの変化や性格、情景について、場面の移り変わりと結び付けて具体的に想像する。
- 評価対象：各場面の学習後に書いた振り返り記述。記述は1件ずつ独立に判定する。

# 判定に用いる「要素」
- 判定に用いる要素は、物語の内容についての考えである。具体的には、登場人物の行動・気持ち・性格、情景、場面の出来事、場面と場面のつながり、作品の主題について述べた考えを指す。
- 学習の進め方や学習活動についての記述（例：音読した、本文を読み返した、考えを書いた、友達や先生の考えを見た・聞いた、話し合った、発表した、楽しかった、難しかった）は、それ自体を要素として数えない。こうした記述を含む文は、物語の内容についての考えを述べている部分だけを判定に用いる。
- 考えの出どころ（自分で考えたか、友達・先生・教科書などから得たか）は判定に用いない。「友達の意見で」「〇〇さんの考えを見て」「みんなと違って」などの表現があるかどうかで、レベルを上げることも下げることもしない。他の人の考えとして紹介されている内容も、物語の内容についての考えであれば、他の部分と同じ基準で要素として扱う。
- 自分の考えが変わったことを述べていても、そのこと自体はレベルの根拠にしない。変わる前と後の考えを、それぞれ物語の内容の要素として扱う。

# 評価基準（SOLOタクソノミー）
- Level 1 Pre-structural（前構造的）：物語の内容についての要素がない。空欄、物語と無関係な記述、学習活動や感想だけの記述（「楽しかった」「よく分かった」など）、意味をなさない記述。
- Level 2 Uni-structural（単一構造的）：物語の内容についての要素が1つだけ述べられている。例：登場人物の気持ちを一つの語や一つの事柄で述べるだけで、理由や他の要素とのつながりがない。
- Level 3 Multi-structural（多重構造的）：物語の内容についての要素が2つ以上述べられているが、並べて述べられているだけで関係づけがない記述。または、要素どうしの結び付きが1つだけの記述（例：一つの出来事と一つの気持ちを「〜から」「〜ので」で結ぶだけで、それ以上の説明がない）。
- Level 4 Relational（関係構造的）：2つ以上の結び付きが組み合わさって、まとまった説明になっている記述。例：登場人物の気持ちを行動・出来事・描写から読み取り、さらにその気持ちの理由や変化、場面の移り変わりと結び付けている。複数の場面や複数の人物の気持ちを比べたりつなげたりして説明している。
- Level 5 Extended Abstract（拡張抽象的）：Level 4の関係づけに加えて、その場面や物語の具体的な内容を超えた一般化・抽象化がある。例：作品全体の主題（すれ違い、後悔、償いなど）としてまとめている。人の気持ちや人との関わり方についての一般的な考えに広げている。自分の経験や他の物語に当てはめて考えている。

# 判定の手順
1. 記述から物語の内容についての要素を取り出す（学習活動についての記述は除く。考えの出どころは問わない）。
2. 要素の数を数える（0、1、2以上）。
3. 要素が2つ以上あるとき、要素どうしの結び付き（理由、原因と結果、場面と気持ちの対応、気持ちの変化、場面どうしの比較やつながり）の数を数える（なし、1つ、2つ以上）。
4. 結び付きが2つ以上あるとき、具体的な内容を超えた一般化・抽象化があるかを判断する。
5. 次のとおりレベルを決める。要素が0→Level 1。要素が1→Level 2。要素が2以上で結び付きがなし、または1つ→Level 3。結び付きが2つ以上→Level 4。結び付きが2つ以上で一般化あり→Level 5。

# 留意事項
- 文字数の多少で判断しない。短くても2つ以上の結び付きがあればLevel 4、長くても並べているだけ、または結び付きが1つだけならLevel 3とする。
- 「〜から」「〜ので」などの接続の言葉があるだけでは関係づけとみなさない。物語の内容の要素どうしが意味のうえで結び付いているかで判断する。
- 学習の進め方についての一般的な気づき（例：本文をよく読むと分かる、場面ごとに気持ちを考えるとよい）は、物語の内容の一般化ではないため、Level 5の根拠にしない。
- 誤字・脱字や表記は判定に影響させない。
- 迷った場合は低い方のレベルを選ぶ。

# 出力形式
次のJSONだけを出力してください。前置きや説明は書かないでください。
{
  "物語内容の要素の数": "0" または "1" または "2以上",
  "要素間の結び付きの数": "なし" または "1つ" または "2つ以上",
  "具体を超えた一般化": "あり" または "なし",
  "SOLOレベル": 1から5の整数,
  "判定理由": "50字以内で判定の根拠を述べる"
}
````
